# Sources

Do not paste this file into a student text. Student texts stay short and plain.

Search only the sources the student turned on during setup. Read `show-setup` for that list. Skip a source that is not connected. A failed login does not cancel the other sources.

Check email job alerts first. They ride the student's already connected email and still work when a board login fails.

Then each connected board, in this order: LinkedIn, Handshake, JobRight, Simplify. Other boards the student named are last. About ten sources is the ceiling. Add a new one here before using it.

For each source, record the employer, the official job URL, and the job id described in `references/screening.md`.

| Source | Where new roles are | Sign-in | Notes |
| --- | --- | --- | --- |
| Email alerts | The student's connected inbox. Subject lines about jobs, alerts, and recruiter mail. | Already connected email. If email is not connected, ask them to connect it and skip alerts this run. | Open the official posting before a verdict. The email is a clue. |
| LinkedIn | Jobs the student can see while signed in. | Browser. Student signs in once. Two-factor is handed to them. | Also an apply route when the posting uses Easy Apply. |
| Handshake | The student's school job board. | Browser sign-in. | School portal pages differ. Say which school the saved setup names. |
| JobRight | The student's JobRight matches. | Browser sign-in. | Use the outbound link to the employer page for the verdict. |
| Simplify | The student's Simplify matches. | Browser sign-in. | Use the outbound employer or applicant-system link. |

## Apply routes

Fill the form on the official applicant page the posting uses. Step-by-step support is LinkedIn, Handshake, Greenhouse, Lever, and Ashby. Any other form, a captcha, or a two-factor prompt: fill what matches, hand the browser to the student, and wait. Do not submit on any route until they approve the filled package.
